# 我的川农 iOS 迁移与验收记录

更新：2026-10-23。迁移依据为本工作区 `my-chuannong-android` 当前川农 APK 对应源码。Android 参考分支 `codex/module-operations`，公告修复提交 `5a14c7c`。iOS 为原生 SwiftUI / WebKit / WidgetKit 实现；当前主体代码已移植，已进入统一编译、业务验收与问题修复，**尚未通过完整验收，不是最终交付**。

## 用户要求

- UI、页面结构、绿色主题、功能与交互流程按自己的川农 Android 逐项对齐；不拿“我的长理”或云岭星球作为产品基础。
- 云岭星球仅可局部研究动画和交互，当前未导入其源码。
- 公告使用“服务”页头条下方、学习上方的原有“服务动态”卡片区，不新增“校园公告”栏目。
- 先移植全部代码，再集中测试、修复、复测。移植中允许仅为展示真实 SwiftUI Canvas 进行编译，不提前开展业务验收。
- Xcode 源码与固定 Canvas 保持可见。`AppVisualPreview` 使用实际页面组件及明确标为预览的公告，不加载真实登录缓存、不上报设备、不轮询后台。
- 最终使用用户提供的本机测试凭据，完成自行登录、实时刷新课表、关闭重开恢复、会话过期恢复及账号隔离测试；发现问题修复复测。实际文档是同一学号的川农 e 与教务两套凭据，不是两位学生；第二位学生只能做合成隔离测试。凭据不进入仓库、聊天、日志或截图交付。验证码按实际界面工具要求在相应步骤处理。

## 共用服务与独立配置

业务 API 继续共用 `https://chuannong-api.mychangliapp.cn/api/v1/`，无需另做用户数据库或另开 iOS 业务域名。平台账号、公告、资料库、社区、机构和预约复用既有后台。学校账号、Cookie、教务自动恢复凭据、课表、成绩只在设备保存，与平台请求隔离。

iOS 设备上报与 App Store 更新策略已于 2026-10-23 部署到现有生产后台，HTTP 契约及新旧平台兼容测试通过；Android 现有字段和 APK 更新路径保留。高德需独立 **iOS Key** 并绑定 Bundle ID，Android Key 不通用。当前开发 Bundle ID `com.mychuannong.app.development`，已在高德“我的川农”应用下创建“川农iOS开发”Key 并写入仓库外本机配置，模拟器与真机目标编译产物的 Bundle ID / Key 匹配已核验。签名、App Group 与正式分发需匹配 Apple 配置。

## 工程与资源

- Xcode 工程含 App 与 Widget 两个目标，Swift 6 严格并发，iOS 17 起。
- 核心模块 `Core/` 与 App 分离，方便对解析/身份/缓存/URL 策略进行有意义的测试。
- 自有品牌原图及指南图保持原文件；`Scripts/generate-assets.swift` 生成 Apple 要求的图标资产。
- `Scripts/update-project.py` 确定性维护所有 Swift 文件、资源、Widget 与 SDK 引用。
- 高德官方 SDK：地图 11.3.100、Foundation NO-IDFA 1.9.4、Search 9.8.1 与配套隐私资源。`Scripts/install-amap.py` 使用固定 SHA-256 校验本地官方包。此 SDK 无 Apple Silicon 模拟器切片，因此模拟器不能验收原生地图；真机实现单独编译与验收，不伪装地图已可用。
- `Config/Local.xcconfig`、Vendor、DerivedData、`.work/`、outputs、测试凭据与真实截图均不提交。
- 课程提醒使用系统本机通知队列，最多预排 60 条，回到前台更新；不可将其宣传为无限期后台调度或 APNs 远程推送。

## 整体验收顺序与交付门槛

1. 模拟器/设备目标编译，核心测试、后端新旧平台兼容测试，逐项修复。
2. 使用实际可用账号完成川农 e、教务、身份绑定；比对学校课表，主动刷新验证更新时间与内容来源，失败缓存保护。两位学生的真实隔离测试需要确有第二位学生凭据。
3. 关闭重开、模拟器重启、Cookie 恢复、服务器过期/失效路径、默认安全保存与有限恢复、账号 A/B 隔离、解绑后不可恢复旧会话；不修改学校密码或关闭校方验证。
4. 全部功能导航、读写、撤回、通知、设置与 Android UI 核对；涉及生产写入仅使用授权的验收记录，结束后回收。
5. 汇总真实通过项、失败修复与仍受外部配置限制的项目。长期保存需写明实际观察时长和过期边界验证，不能用短时间重启宣称已验证数周。

以上尚未完成前不交付“所有测试通过”的结论。当前模拟器与 unsigned 真机目标构建通过；33 项核心测试（含真实 WebKit 表单序列化、认证页布局、学校超时分类、服务路由和 SSO 主身份回归）、原后端 127 项回归、新增 5 项 iOS 契约测试与 10 项设备统计定向回归通过。测试有重叠，不合计为独立用例总数；这些结果不能替代真实业务测试。

实际读取用户文档后确认，它包含同一学号的川农 e / 教务两套凭据，而非两位学生。上文双账号验收要求按实际可用凭据执行两段认证；第二位学生的账号隔离只能报告合成测试结果，不能声称真实完成。

实际登录阶段发现：禁用签名的模拟器构建导致系统 Keychain 返回 -34018（缺少权限），旧提示误导为解锁设备。改为开启模拟器 ad-hoc 签名以生成模拟权限，错误提示区分签名与设备锁定；真实写入、App 强制重开和模拟器完整重启后恢复已通过。用户明确授权使用 XCTest UI 自动化完成测试；凭据仅本机读取，测试附件关闭，剪贴板只在粘贴时短暂使用。

随后定位教务登录失败的真实返回为“登录类别错误，请重新登录！”。原 iOS 对页面 `lb` 控件赋值不能保证浏览器提交唯一学生类别。现与 Android 对齐，在学校 WebView 内提交明确的 `user/pwd/lb=S/submit/sign/hour_key` 六字段表单，保留原字符集和新鲜动态字段，校验相同学校代理路径。2026-10-22 20:54 实际教务登录及本人身份核验成功，首次同步课表与 25 行成绩，考试页成功返回空状态；20:55 主动刷新时间前进，随后 App 重开、模拟器关机启动后再次刷新均成功，全程无需重输密码。这里只证明本次短时恢复，不声称已观察数周登录。

继续验收时，教务真实返回“系统提示：登录超时，请重新登录！”。修正学校 JavaScript 弹窗错误分类，使该响应进入有限自动恢复，而“登录类别错误”、密码错误和验证码要求不会误触发自动重试。已在不重输账号密码的情况下恢复学校会话，21:09:50 再次成功刷新同一账号课表。该结果验证真实超时响应的恢复，不证明超时具体成因或数周保持时间。

服务中的教务入口同时按 Android `SchoolWebSessions.academicEntry` 对齐：先验证/恢复当前身份，再进入 `PERSONAL_INFO`；不再把已绑定用户带回公共登录首页。入口实测成功，网页底部工具栏也已与主标签栏分开，避免遮挡。

另修正提醒的系统请求并发顺序，避免解绑或关闭提醒后旧添加请求重新入队；延后提醒核验当前学校账号且串行执行。此修正已构建，系统行为仍待验收。

## 2026-10-22 全局学校认证与输入布局回归

用户纠正后，停止使用模拟器内的“我的长理”APK 作川农界面基准，保留自有川农 Android 源码作为迁移依据。按用户要求只读获取 GitHub `ForgeRock/exampleOAuth2Clients` 的 WKWebView SSO 示例，核对 Cookie 注入完成后再导航的原则；未把参考源码导入 App，也未采用其普通配置文件存 Cookie 的旧方式。

本轮定位与修正：

- 移除所有学校服务必须先有 VPN 资源映射的错误门禁。统一认证、一网通办和学工走各自官方入口，共享同一学校 WebKit 存储和 Keychain Cookie 快照，平台账号保持独立。
- 川农 e 的服务端主身份单独确认和保存，不依赖教务绑定。跨服务由官方认证接口签发当前服务票据，校验主身份，不复制 Cookie 到另一域，不把委托身份当作本人。
- 学工业务页在缺少自身 token 时会跳到学校 `/sso/logout`；改先进入其公开 `/mobile/sso?redirect=…`，按学校正常链路取回会话，再到原综测、周点名或节假日页面。旧网页的异步检查不能覆盖新导航，避免把认证中途拉回大厅。回退跳过认证中转页，返回目标失败有上限。
- 去掉教务“保存密码”勾选和单独关闭恢复的按钮。实际本人身份核验成功后默认写入不参与同步的 Keychain，供有限恢复；保留解绑清除。按用户要求未修改隐私政策正文。
- 外部认证使用全屏容器，键盘出现时保持网页布局高度，认证输入文字最小 16 CSS px、使用设备宽度 viewport；保留用户手势缩放和键盘遮挡时的必要滚动。实际 iPhone 17 Pro 模拟器上，账号/密码聚焦前后宽度 402、页面缩放 1，账号框仍在 y=365，密码框 y=424；验证码位置被键盘遮挡时可正常滚动到可见区域。
- 临时预览会话禁止写入 Cookie、清理真实凭据或学习缓存、更新真实提醒。排查中使用的测试启动参数及诊断采集代码已移除。另修正“我的”设置行中间空白处不能点击的问题。

本轮实际测试：已有学校会话下的统一认证、一网通办、学工、综测、周点名、校园缴费均免重复输入密码；综测显示实际学年和排名项，周点名显示学校任务列表，缴费到达本人缴费首页；节假日去向进入目标页面并显示学校空状态“未能找到相关信息”。仅验证进入与读取，未提交签到、去向表单或付款。

另用临时测试状态排除教务身份，只完成一次真实川农 e 认证后，即可进入综测；随后恢复正常状态，教务原生登录在无保存开关下成功。App 重开后课表主动刷新成功。移除临时诊断后的最终签名构建已安装并核对二进制一致；完整关闭/启动模拟器后，无需输入密码，课表于 21:58 更新为 25 个课程时段，学工亦恢复进入。真实教务服务器超时恢复已有本日 21:09 的验证记录；上述短时回归不代表已观察数周登录，也不绕过学校主动失效或强制验证。

最终本轮核心测试 33 项通过，模拟器签名构建和 unsigned 真机目标编译通过；真机编译不等于真机操作验收。自动化控制期间发生过一次 XCTest Runner 的意外退出，恢复 Runner 后完成上述回归；未据此宣称 App 崩溃或测试通过。完整迁移表中其余待验收项和地图配置/真机限制仍保持原状态。
